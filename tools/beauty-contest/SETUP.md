# Beauty contest — live-poll setup (Firebase Realtime Database, free)

The Keynesian beauty contest tool has two pages:

- `index.html` — the **instructor / projector** page (linked from the landing
  page). Without any setup it runs in **simulation mode** (a seeded class of
  level-k reasoners) and shows a dismissible notice pointing here.
- `submit.html` — the **student phone** page (joined via the QR code / session
  code on the projector). It needs the live channel below.

The live channel is a **Firebase Realtime Database used through its plain
REST interface** — no Firebase SDK, no build step, nothing to maintain.
Students `POST` guesses; the instructor page live-subscribes via
`EventSource` (the RTDB REST API streams server-sent events natively).

## One-time setup (~10 minutes, zero recurring cost)

1. Go to <https://console.firebase.google.com> → **Add project**. Any name
   (e.g. `fin30600-beauty`). Disable Google Analytics. New projects are on
   the **Spark (free) plan** — this game's traffic (a few thousand tiny
   writes per semester) is far below every Spark limit, and Spark has no
   billing account, so there is nothing that can accrue cost.
2. In the project: **Build → Realtime Database → Create database**. Pick the
   default US region, start in **locked mode**.
3. In the database's **Rules** tab, replace the rules with the JSON below and
   click **Publish**.
4. Copy the database URL shown at the top of the Data tab — it looks like
   `https://<project>-default-rtdb.firebaseio.com` (or
   `https://<project>-default-rtdb.<region>.firebasedatabase.app`).
5. In this folder:

   ```bash
   cp config.example.js config.js
   ```

   paste the URL into `config.js`, and **commit `config.js`** — the URL is
   public by design (every student's phone fetches against it); all security
   lives in the database rules.
6. Optional: set `shortJoinUrl` in `config.js` to a short typed-in address to
   display on the projector (Christian's: `christiankontz.com/play`, a tiny
   redirect page at `play/index.html` in the `cg89x.github.io` repo that
   forwards to this tool's `submit.html`, preserving `#s=CODE` / `?s=CODE`).
   The QR code always deep-links directly with the session code; the short
   URL is for students who type instead of scan — they enter the code on the
   submit page.

## Security rules

```json
{
  "rules": {
    ".read": false,
    ".write": false,
    "beauty": {
      "$session": {
        ".read": true,
        "meta": {
          ".write": true
        },
        "rounds": {
          "$round": {
            "guesses": {
              "$g": {
                ".write": "!data.exists()",
                ".validate": "newData.hasChildren(['v']) && newData.child('v').isNumber() && newData.child('v').val() >= 0 && newData.child('v').val() <= 100"
              }
            }
          }
        }
      }
    }
  }
}
```

What they enforce:

- Everything is locked except `beauty/<session>`.
- Anyone who knows a session code can **read** that session (the instructor
  page streams it; students only ever read `meta`).
- `meta` is writable (the instructor page opens/closes rounds with no auth).
- Each guess is **write-once** (`!data.exists()` — no overwrites or deletes
  via the API) and must contain a numeric `v` between 0 and 100.

## The honest tradeoff

There is **no authentication**. A determined student who reads this code
could spam extra guesses into a round or even flip `meta` themselves. That
is an accepted tradeoff for a 5-minute classroom game — the stakes are a
prize and a laugh, session codes are random 4-character strings, and a new
session is one click. If a round ever looks poisoned, click **New session**
and replay.

Housekeeping: guesses are write-once, so stale sessions can't be deleted
through the REST API — every month or two, open the Firebase console's Data
tab and delete old children under `beauty/` (the console bypasses the
rules). Total data is tiny (~100 bytes per guess), so even skipping this
costs nothing.

## Data model

```
beauty/{SESSION}/meta                             {round: 1, open: true, created: <ms>}
beauty/{SESSION}/rounds/{r}/guesses/{pushId}      {v: 41.7, name: "Ann" (optional), t: <ms>}
```

Session codes: 4 characters from `ABCDEFGHJKMNPQRSTUVWXYZ23456789`
(unambiguous — no 0/O, 1/I/L), generated by **New session** on the
instructor page.
